# everypath 要件定義書

上位仕様。AI と人が作業のたびに参照する。100 行以内。更新は決定記録を伴う。
詳細な設計は `SPEC.md` にある。この文書は `SPEC.md` の判断基準を短く固定するもので、両者が食い違えばこの文書を優先し、`SPEC.md` を直す。

## 目的

AI にコードを書かせている開発者が、自分のアプリの振る舞いをステートチャートとして俯瞰し、ありうる経路すべてを検査できるようになる。使う前は、テストで試した経路しか見えず、AI が増やした機能の全体像と依存を人が追えない。使った後は、AI が宣言したモデルを TLA+ で全探索した反例が図の上の赤い経路として返り、どこを見るべきかが色で分かる。

利用者は、まず作者本人（個人開発で Claude Code を使う）。次に npm 公開後の不特定多数で、`npx everypath` を叩いた瞬間に動くことを前提にする。UI、README、スキル、生成する指示文はすべて日本語で書く（決定 0001）。出典: `SPEC.md` §1、ラウンド 1 の回答。

## 不変条件

どんな状況でも守ること。各項目は判定できる文。確かめ方を添える。

| ID | 不変条件 | 確かめ方 | 強さ |
|---|---|---|---|
| R-01 | 対象リポジトリのソースを変更しない。everypath が書くのは `.everypath/` 配下と、`init` が配る雛形（`everypath.*.json`、`.claude/`）だけ | `test/requirements.test.ts`: `scan` と `check --tlc` の前後で `.everypath/` 以外の全ファイルの hash が一致する | 強 |
| R-02 | `package.json` の `dependencies` が空で、`dist/ui.html` にネットワーク参照（`http://`、`https://`、`//`）が無い | `scripts/verify-requirements.ts` が `package.json` と `dist/ui.html` を検査し、`prepublishOnly` で走る | 強 |
| R-03 | Java と `tla2tools.jar` が無い環境でも、`scan`、`check`（簡易検査）、`serve`、承認、指示生成が動く。TLC が要る操作は導入手順を案内して続行する | `test/requirements.test.ts`: `java` の無い `PATH` で `check` が exit 0/1 で終わり、`/check/tlc` が案内文を返す | 強 |
| R-04 | モデルは有限集合に閉じる（変数型は `BOOLEAN`、`0..N`、列挙のみ）。文法外のアノテーションは `graph.json.warnings[]` に積み、その遷移をガード無しとして扱い、スキャンをエラーで止めない | `test/expr.test.ts`: 文法外入力 10 件が warning になり `scan` が exit 0 | 強 |
| R-05 | 対象リポジトリのファイル保存から、ビューアに新ノードと矢印が現れるまで 2 秒以内。既存ノードの座標は変わらない | `scripts/verify-requirements.ts`: ファイル追加から SSE `graph` 受信までの時間を 10 回計測して最大値を見る。`layout.json` の既存 id の座標を前後比較する | 強 |

強さ: スクリプトやテストで機械的に確かめられるものは「強」、目視だけのものは「弱」。弱いものは後で強くするか、不変条件から外す。

## 非目標

やらないと決めたこと。理由を 1 行。

- 図の手動編集（ノードやエッジの追加・削除）。図は常にコードから生成する。ドラッグでの置き場所の記憶は「図を直す」ではないので対象内。
- コードの自動修正。everypath は読み取り専用で、指示文を生成してエージェントに渡すまで。
- ダークモード。色が意味を持つ UI なので、配色を 2 系統維持しない（`SPEC.md` §17.7 を確定）。
- 英語化・多言語切替。利用者は作者本人と日本語の OSS 利用者（決定 0001）。
- ホスト版・共有サーバー。ローカルの `everypath serve` だけ。
- エディタ拡張（VS Code、JetBrains）。ブラウザのビューアと CLI だけ。
- Claude Code 以外のエージェント専用の連携。`graph.json` と指示文は中立に保つので、専用スキルやプラグインは作らない。
- TLA+ 以外のチェッカ（Apalache、Alloy）への切替。`SPEC.md` §16 フェーズ 3 から外す（決定 0002）。

後回し（やる予定だが今回ではない。`SPEC.md` §16 フェーズ 2、3）: 観測遷移と乖離チェック、Mermaid 出力、階層状態、関数単位の証明アダプタ、Go/Rust/Java の import 解決、チーム向け機能。

## 用語

| 用語 | 定義 | 型名 |
|---|---|---|
| 状態 | ステートチャートの状態。図上の箱。人間の粒度の画面・モード・機能で、1 状態 = 1 つ以上のソースファイル。「ノード」は図の上での呼び名で同じもの | `StateNode` |
| 検査状態 | 状態に重ねるレビューと検証の結果（tested、vuln、wip、planned、reviewed、proof）。「状態」と混同しないよう、コードでは `status` と呼ぶ | `NodeStatus` |
| 遷移 | `@state-next` で宣言した状態間の移動。イベント、ガード、代入を持てる。図では実線 | `Edge`（`type: "flow"`） |
| 依存 | import / require から抽出した参照。検査対象外。図では点線 | `Edge`（`type: "dep"`） |
| イベント | 遷移を起こすきっかけの名前（`on:`）。環境が非決定に選ぶ。無名の遷移は `tau` | `EventName` |
| 変数 | ステートチャートが持つ有限の状態変数。`@state-var` で宣言する | `ModelVar` |
| 性質 | モデルに常に成り立つべき条件。AI が提案し、人間が承認する。グラフ性質とモデル性質の 2 系統 | `Property` |
| 反例 | 性質を破る具体的な経路。状態の列と各ステップの変数値 | `Counterexample` |
| 簡易検査 | 内蔵 BFS。変数を無視した過大近似。保存のたびに走る | `checkedBy: "bfs"` |
| モデル検査 | TLC による全探索。手動または CI で走る | `checkedBy: "tlc"` |
| 承認 | 人間が状態の仕様を確認した記録。ファイル hash と紐づく。機械の「検証」とは別 | `Approval` |
| 親、葉 | `@state-parent` で子を持つ状態が親、子を持たない状態が葉。検査と TLA+ は葉だけの平らなモデルを読む。名乗るファイルの無い親は入れ物 | `StateNode.parent`、`Leaf`、`StateNode.container` |
| 入口 | 親へ遷移したときに入る葉。`@state-initial` の付いた子をたどって決まる | `Hierarchy.enter` |
